Hover fires more than any other interaction. Sweep the cursor across a nav
and you can cross ten items in a second. If each one fades in, the
interface is always a few frames behind the pointer, and it reads as slow
even when nothing is.

The rule that follows: **the more often something happens, the less
animation it can afford.** Move across both menus below.

<HoverRestraintDemo />

The right one switches its highlight on with no transition at all. Instant
is the correct default for hover. If a color change feels harsh at full
speed, you can soften it, but keep the transition under 100ms. Past that
people start to feel the lag.

## Tooltips

Tooltips are the one hover case where a delay helps. Without one they pop
up while you are just passing through on the way to something else. So the
first tooltip should wait, around 400ms to 700ms, and then its neighbors
should appear at once. You have already shown you want the labels, and
making you wait again for each one is the same lag from the first demo.

<HoverTooltipDemo />

Hover the toolbar, wait for the first tooltip, then slide across. The rest
follow the cursor without the delay and without the enter animation.

## Keyboard actions

The same thinking applies away from the pointer. Press the button below, or
use the shortcut, a few times in a row.

<KeyboardActionDemo />

Someone toggling a sidebar with a shortcut is your fastest user. They are
not looking for the panel to arrive from somewhere. They already know what
the shortcut does, and a 250ms slide charges them for speed they came for.
The instant version feels like the shortcut itself: press, done.

The line to draw is by frequency and intent, not by input device. A modal
that opens once a session can animate. A panel you flip forty times a day
should not.

## Usage

The tooltip behavior comes from the library. Base UI marks a tooltip that
opened without its delay with `data-instant`, and you switch the animation
off for that case.

<CodeBlock
  tabs={[
    {
      label: "Tailwind",
      language: "html",
      icon: "tailwind",
      code: `<div class="animate-in fade-in-0 zoom-in-95 duration-150 data-instant:duration-0">
    Bold
</div>`,
    },
    {
      label: "CSS",
      language: "css",
      icon: "css",
      code: `.tooltip {
    animation: tooltip-in 150ms var(--ease-out);
}

.tooltip[data-instant] {
    animation-duration: 0ms;
}`,
    },
  ]}
/>

The test is simple. Sweep the cursor across the component as fast as you
can. If highlights are still catching up to where the cursor is, something
is animating in when it should just appear.
